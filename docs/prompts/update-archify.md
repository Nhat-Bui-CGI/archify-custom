# Update Archify Custom

Update the Archify Skill this harness actually loads using https://github.com/peterbuitho/archify-custom. This is the original Archify by tt-a1i with additional official Azure icons.

Handle discovery, download, backup, replacement, and verification yourself. My request authorizes updating that installation only. Ask only if a necessary choice cannot be determined from this session or the harness configuration.

1. Identify the active Archify installation from its loaded `SKILL.md` path or harness configuration. If several copies exist, update only the active one. If the active path is uncertain, ask me. If no installation exists, report that instead of choosing a new installation scope. Resolve installer-managed destinations and symbolic links before changing them; if ownership is unclear, ask me.
2. Find this repository's newest published release that has an uploaded asset named `archify.zip`. Include prereleases, exclude drafts, and compare publication dates rather than tag names. Use the releases list or GitHub releases API, including additional pages when needed; `/releases/latest` can omit custom prereleases. Pin that release and asset for this operation. Download its `archify.zip` asset, not a source-code archive or an upstream package.
3. Extract into a temporary directory. Verify the downloaded archive against the release asset's SHA-256 digest or published checksum when available. Stop on a mismatch; if no checksum is published, state that verification is unavailable. Check for `archify/SKILL.md`, `archify/package.json`, and `archify/bin/archify.mjs`. Read the package's Node.js requirement and check the available runtime before changing the existing installation. If a compatible runtime is missing, leave the existing installation intact and report the prerequisite.
4. Stop any preview using that installation. Back up the complete existing folder outside all Skill discovery directories. Preserve personal files and edits in that backup. Replace the complete installed package with the extracted `archify` folder at the exact original path, without an extra nested folder or stale files. If the installed package already matches the selected release, leave it in place and verify it.
5. From the installed folder, run `node bin/archify.mjs brands azure-openai --json` and `node bin/archify.mjs brands container-apps --json`. Require successful exits, `ok: true`, and the requested icon IDs. If the selected release documents replacement commands, use those instead. If replacement or verification fails, restore the complete backup.

Keep the backup. Do not copy old bundled files over the updated package. Merge personal additions only when they will not overwrite the new package's files; report any remaining edits needing a merge.

Finish with the updated path, selected release tag, downloaded ZIP's SHA-256, verification result, backup location, and whether I need to start a new session. Use the release tag and archive hash to identify the custom build, since its package version can match upstream. Future custom packages must come from this fork; upstream update reminders may refer to a different release stream. Do not update other harnesses or installations.
